How to use the regex tester

  1. Type your pattern without the surrounding slashes, and tick the flags you need.
  2. Paste some test text. Matches are highlighted as you type, and capture groups are listed in a table.
  3. Tick "Preview a replace" to see the text after a find-and-replace, using $1 or $<name> for groups.

Worked example

Pattern \b\d{4}-\d{2}-\d{2}\b with g Text "sent on 2026-10-13, paid by 2026-11-12" Matches 2026-10-13 (at 8) and 2026-11-12 (at 28) Pattern (\d{4})-(\d{2})-(\d{2}) replace with $3/$2/$1 Result "sent on 13/10/2026, paid by 12/11/2026"

Patterns for things like email addresses or postcodes get complicated fast and still miss real cases. For checking input, a simple pattern plus a real check (such as sending a confirmation email) usually works better.

Frequently asked questions

Which regex flavour does this use?

JavaScript's, as built into your browser. Most patterns work the same in Python, Java, PHP and .NET, but some features differ, such as lookbehind support and how named groups are written. Test in your own language before relying on a pattern.

Why did it say "stopped after 1 second"?

Some patterns, especially nested repeats like (a+)+, can take an extremely long time on text that almost matches (called catastrophic backtracking). We run the match in the background and stop it after a second so the page doesn't freeze. The same pattern could slow down a real program, so it's worth rewriting.

Is my text sent anywhere?

No. Matching happens in your browser.

How Base64 works

Base64 turns any data into 64 safe characters (A–Z, a–z, 0–9, + and /) so it can travel through email, web addresses, JSON and other places made for text. Text is first turned into bytes using UTF-8, then every 3 bytes (24 bits) become 4 characters of 6 bits each. If the last group is short, = signs pad it. So Base64 is always about a third bigger than the original.

"Man" bytes 77 97 110 → bits 010011 010110 000101 101110 → TWFu "Ma" → TWE= "M" → TQ== Size ≈ 4 × (bytes ÷ 3, rounded up) characters

Worked examples

Hello, world! → SGVsbG8sIHdvcmxkIQ== Hello, world! 👋 → SGVsbG8sIHdvcmxkISDwn5GL (the emoji is 4 bytes in UTF-8) URL-safe "??>" → Pz8- (standard: Pz8+)

Frequently asked questions

Is Base64 encryption?

No. Anyone can decode Base64, so it hides nothing. Never use it to protect passwords or private data.

What's URL-safe Base64?

Standard Base64 uses + and /, which have special meanings in web addresses. URL-safe Base64 (described in RFC 4648) uses - and _ instead and usually drops the = padding, so the result can go straight into a link or file name. Our decoder reads both.

Why does decoding say "it isn't text"?

The Base64 is fine, but the data inside is something else, such as a picture. Pictures are often stored as data URLs starting with data:image/png;base64,.
